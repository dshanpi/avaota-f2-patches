## 采集方法

每档分别运行存图和无存图配置，各 35 秒；约第 10 秒和第 30 秒读取 VI 计数和 uptime。下表 fps 为 VI 硬件计数差除以实测时间差（约 20 秒），不是仅照抄配置值。所有模式检查 Sensor 输入/输出尺寸、四 Lane 状态、ISP 参数匹配和退出结果。

720p/4K 使用独立应用示例补丁，其他模式用此次新编译的原版 `sample_virvi`。两种程序均链接原厂 ISP 参数。SDK 的示例源文件和原版二进制在构建独立测试程序后已恢复，应用补丁单独提供在 `test/`，不混入四文件 SDK 增量。

## 配置差异

- 720p/1080p/2K：video0、ISP0、stitch_mode=0。720p 使用 `AW_MPI_ISP_SetD3dLbcRatio(isp, 100)`，本轮未复现之前的 D3D 压缩停流问题。
- 4K：video1、ISP1、stitch_mode=1，使用 SDK 的单帧左右分块和合并，最终输出完整 3840×2160。应用请求两个 YUV 缓冲。
- 所有模式共用原厂 `ov13850_mipi_isp610_20261021_195907.h`，没有新增独立画质标定；默认仍为 2K30，不需要模块参数。

## 图像和模式切换检查

七张 NV21 均按对应尺寸转换并实际查看：有桌面、设备、天花板和窗框场景，画面完整，没有明显半幅缺失或横向错位；4K 未看到明显分块合并断裂。光照和视场不同，未经色卡/分辨率卡评价，不能据此宣称完成 ISP 画质标定。

4K 的存图和持续收帧两次运行都在停止边界各出现一次 `tdm0 rx0 frame error`（约 uptime 577.509s 和 621.277s，紧接着 Sensor stream off）；收帧统计窗口内没有该错误。**该停流告警尚未修复**，原始日志保留在诊断摘要中，未通过屏蔽日志来消除。

为检查停流后的可用性，又从 4K 切回 2K60，运行 35 秒，约 20 秒统计窗口测得 **59.960fps**，lost/error 增量均为 0，程序正常退出。详见 [切换回归数据](multimode-post4k-regression.json)。这支持本轮模式切换可用，不等于停流告警已被修复。

## 保留的问题与边界

开流仍有偶发 TWI/SCCB 超时及写重试，重试后本轮均完成采集；按此前要求未扩大修改范围去改 I²C 公共驱动。原厂 ISP 参数与 SDK 之间仍有 AE table invalid、AWB 字段及 TDM 调试事件/退出顺序等告警，应按采集日志判断，不能宣称日志已全部清零。没有据此改写原厂参数。

本轮验证 Sensor/VI/ISP 图像输出，不包含 H.264/H.265 编码测试、长时间录制、跨温度测试或完整画质验收。显示场景在测试期间有变化，不能把不同模式的图片直接作为同场景画质对比。

原始数据摘要见 [runtime-summary.json](multimode-runtime-summary.json)，内核增量告警见 [runtime-diagnostics.json](multimode-runtime-diagnostics.json)。用户复测步骤在仓库 README；需要长时间测试时应使用 stream 配置并另外统计应用交付/编码帧率。
